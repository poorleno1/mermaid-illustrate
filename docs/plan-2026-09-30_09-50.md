# Plan: adopt mermaid-illustrate for Azure / Azure DevOps architecture diagrams

## 1. What the repo is

An Agent Skill (`SKILL.md` + 25 on-demand reference files in `examples/`) that tells an agent how to write
Mermaid diagrams in one style ("Blueprint", IBM Carbon v11 colors). It is a fork of `zhiweio/mermaid-illustrate`.
The structure is sound: small entry file, reference material loaded only when needed.

## 2. Problems found

| # | Issue | Where | Impact |
|---|---|---|---|
| 1 | "Dark-mode ready" is not true. All `classDef`s are light pastel fills; the dark `themeVariables` only restyle defaults. On a dark page, nodes show up as bright light boxes. | `examples/design-system.md` | Core problem for a dark theme |
| 2 | No idea of a render target. The skill pushes `flowchart`, `@{ img: }`, `@{ icon: }` and `fa:` icons. Azure DevOps wiki supports only `graph`, has no FontAwesome, and does not allow edges to or from subgraphs. | `SKILL.md`, `flowchart.md`, `design-system.md` | Diagrams break in the ADO wiki |
| 3 | Undocumented Mermaid gotcha: a `themeVariables` value containing `-` or `'` makes Mermaid drop the whole `%%{init}%%` block silently (for example `sans-serif` in a font stack). | not documented | Themes silently not applied |
| 4 | Undocumented gotcha: a subgraph with no edges leaving it is laid out in the flipped direction (TB becomes LR) unless it declares `direction`. | not documented | Diagrams turn sideways |
| 5 | Frontmatter `name` is `mermaid-illustrate`; AGENTS.md says it must be `mermaid`. | `AGENTS.md` | Contradiction |
| 6 | Azure icon URL differs: `logos/azure.svg` vs `logos/microsoft-azure.svg`. | `design-system.md` vs `icon-catalog.md` | Minor |
| 7 | Quick-reference card says `bpUser` is a "white fill"; the actual fill is `#f2f4f8`. | `design-system.md` | Minor |
| 8 | README install path for Claude Code is `~/.agents/skills/`; Claude Code reads `~/.claude/skills/` (user) or `.claude/skills/` (project). | `README.md` | Skill not discovered |
| 9 | No layout guidance. Nothing about avoiding crossings, graph size, or shape choice (diamonds grow large with text). | all | Messy diagrams |

## 3. Recommendation: keep it a skill, but make it yours

**Yes, use a skill.** A skill is the right shape: it loads only when a diagram is requested, works in
Claude Code and in other agents that read `SKILL.md` (Copilot, Cursor, Codex, Gemini CLI), and keeps
your global `CLAUDE.md` lean.

Steps:

1. **Own the fork.** Treat this repo as your source of truth rather than tracking upstream. Trim what you do not use.
2. **Pick one theme** from the four proposals in `docs/themes/`. It becomes the canonical dark palette in
   `design-system.md`, using the same `bp*` class names so existing examples keep working.
3. **Add a "render target" step to `SKILL.md`** with two profiles:
   - *Azure DevOps wiki / portable* (default for you): `graph` only, `classDef` + `linkStyle` + `%%{init}%%`,
     no icons, no HTML in labels, no subgraph edges. `sequenceDiagram` for interactions.
   - *Full Mermaid 11* (GitHub, VS Code, docs sites): may use `flowchart`, icons, `architecture-beta`.
4. **Add layout rules** (the ones used to build the proposals):
   - Draw an outer canvas subgraph with `direction TB`, so dark diagrams stay readable on light pages.
   - Keep flows tree-shaped. Side items (artifacts, failure paths) hang off as leaves. Trees lay out with no crossings.
   - Link nodes, never subgraphs. Use hexagons for gates instead of diamonds. Aim for 15 nodes or fewer; split larger diagrams.
   - Font stacks without quotes or hyphens; nothing in `themeVariables` may contain `-` or `'`.
5. **Add a validation step**: render with `npx @mermaid-js/mermaid-cli` and check the output before saving.
6. **Install** into `~/.claude/skills/mermaid-illustrate/` (Claude Code). For agents without skill support,
   add a 3-line pointer to your rules (for example in `~/.claude/rules/azure-devops-wiki.md`): "for diagrams, follow
   `<path>/SKILL.md`, render target = Azure DevOps wiki".
7. **Update your ADO wiki rule.** Azure DevOps now renders standard fenced ```` ```mermaid ```` blocks as well as
   `::: mermaid` (Sprint 274 release notes), so one Markdown source can serve both GitHub and the wiki.

## 4. Theme proposals

Rendered comparison: see the published gallery (link in the chat summary). Source files:

| Option | File | Character |
|---|---|---|
| A | `docs/themes/carbon-night.md` | Current Blueprint colors on dark surfaces, IBM Plex Sans |
| B | `docs/themes/azure-midnight.md` | Azure/Fluent navy and cyan, Segoe UI (native on Windows and in ADO) |
| C | `docs/themes/terminal-neon.md` | Tokyo Night style, soft neon strokes, JetBrains Mono |
| D | `docs/themes/carbon-paper.md` | Light control: current palette, tightened |

All four were rendered with Mermaid 10 and 11: 0 node overlaps, 0 edge crossings, 0 clipped labels.

## 5. Open decision

Which theme (or which mix, for example B's palette with A's font) becomes canonical? After that, apply
steps 2 to 5 to `SKILL.md`, `design-system.md`, and `flowchart.md`, and fix issues 5 to 8.
